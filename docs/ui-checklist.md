# Manual UI checklist (spec §15, §17)

Automatically covered by `crates/material_domain/tests/ui_smoke.rs` (creating a node, connecting
through bevy_noodle, rejecting an incompatible connection, undo, save, move),
`crates/material_domain/tests/input_contexts.rs`, `editor_core`'s `state::tests` and
`material_domain`'s `tests` module (creating/renaming/moving/deleting assets, auto-connect from the palette,
the prompt on close, curve tab edits, constant table edits and clearing references), plus the domain shell in
`editor_core`'s `state::tests` / `ui_smoke.rs`'s `bars` (tools, active domain, close successor, console filter,
Project Settings) and `crates/light_domain/tests/editor.rs` (Light assets menu, environment form, two texture domains). `SHADER_EDITOR_INPUT=curve_drag|curve_add` with
`SHADER_EDITOR_OPEN=common/pulse.curve.ron` plays a point drag / double click on a curve. Before a release, walk through by hand on `examples/sample_game`:

- [+] Without arguments the last project opens; a directory without `Cargo.toml`/`assets/` — a message with the reason.
- [ ] Welcome screen (decision 0018): with no project (first launch, File → Close Project) the logo, version, the grey disclaimer, recent projects (up to 50, hover highlight, a click opens one, its "x" removes it from the list and the config) and Open / New Project with the hook-up snippet show; New Project on a directory without `Cargo.toml` shows the reason, on a crate creates `assets/` + `quillshade/` (with a default `quillshade/project.ron`) and opens it; a directory whose `quillshade/project.ron` does not parse is refused with a message naming the file; the config appears in `<OS config dir>/fe3dback/bevy-shader-editor/config.ron`.
- [ ] Open Project (File menu, Ctrl+O, welcome screen): only our dialog opens — the path field with Browse... next to it, below a separator line the 5 most recent projects by name (full path in the tooltip; a click opens one, the "x" removes it and the list refills while the dialog stays open), Cancel / Open in the footer; with unsaved tabs opening another project (a recent one, the field, Browse...) first asks Cancel / Discard / Save like closing tabs (Cancel keeps the project and the changes; a path that is no project shows its error without asking); Browse... opens the system folder picker (Linux: portal, Windows/macOS: native). New Project: the system folder picker opens at once. Choosing a folder opens / sets up the project, cancelling leaves the dialog where Ctrl+V pastes a path copied in another application and Browse... reopens the picker; Copy in a generated-file tab reaches other applications.
- [ ] Main menu logo is sharp at 100–200 % scale; Help → About shows the logo, version, author, license, disclaimer, and the link opens the browser; Help → Project Page too; Help → Quick Start shows six hook-up steps as tabs — core's 1. Crate and 2. Plugin, then Material's titled "Material: …" (5. Material: Loading is marked optional) — with code snippets, the Rust ones highlighted like the generated-Rust tab; a tab, Back and Next switch steps, Done on the last one closes (`SHADER_EDITOR_DEMO=quick_start:6`).
- [ ] Main menu (decision 0016): File opens New Project / Open Project / Close Project (asks when dirty; the tabs come back on reopen) / Project Settings... / Save / Save All / Quit with right-aligned hotkeys; Edit: Undo / Redo; View: Zen mode, Back / Forward, Show project / Show console / Show properties (see View and Back / Forward below); Assets creates every kind of the active domain (Material: New Pbr … New Gradient Collection; Light: New Environment..., New Texture...; Project: only Generate), New folder... and regenerates (Generate); the mainbar ends with the project name and error count (full path on hover) and has no buttons of one editor kind; the editor topbar under the secondbar (visibly separate from it, the active tab in the topbar's colour) follows the active tab (graph / text / curve / consts / image / texture / gradients / environment / settings, none without a tab); the editor statusbar shows `● unsaved`, `N errors · M warnings` (click: focuses the first problem) and the counts for graph (`N WESL lines`) / curve / consts only.
- [ ] Mainbar and secondbar (design §14.3): the mainbar (on a darker background than all other surfaces) reads logo, File … Help, a separator, the domain tabs (real domains only, names only, no icons; full-height rectangular buttons, the active one on a warm orange fill with brighter text, the others dim and transparent, a disabled one dimmed with tooltip "Module is disabled, enable it in Project Settings first"), then the project name, a separator and the error count; it is as high as before the domain tabs. Clicking an inactive enabled domain tab switches the domain, the active or a disabled one does nothing; Tab reaches the domain tabs after Help. Under it the secondbar spans the window: Back / Forward, a separator, then the tabs (one row; more tabs than fit add whole rows, never a scrollbar; the sidebars start below it); other real domains' tabs are greyed, tool tabs blue; Zen mode hides neither bar (`SHADER_EDITOR_DOMAIN=project`, `SHADER_EDITOR_INPUT=tab:12`).
- [ ] Domains and greying (decision 0045): Material is active after start (or the domain saved in `config.ron`); clicking Light shows its last active tab, or none with the hint "No open tab — open an asset from the project tree" — the left sidebar shows only `light` (`day`, `sky`) and Game Assets only `.ktx2` files, the Assets menu only Light's items, the console only Light's lines; Material's tabs stay in the secondbar but greyed (text, icon, close cross), a click on one switches back to Material; closing the last tab of the active domain leaves no tab active and never jumps to another domain's tab; Ctrl+Tab walks all tabs and switches the domain with them; Back / Forward across tabs of two domains switch the domain; after a restart the active domain and each domain's last tab come back (`SHADER_EDITOR_DOMAIN=light`).
- [ ] Tool tabs and Project Settings (decision 0045): File → Project Settings... opens one "Project Settings" tab — no icon, dark blue (brighter when active), never greyed; opening it again activates the same tab; while it is active the left sidebar, Assets menu and console stay the previously active real domain's; the tab shows `quillshade/project.ron` in the editor topbar, General (project path with the full path on hover, format version read-only, Header date) and one section per real domain (Material, Light) with "Used in game"; a change marks the tab unsaved and is one Ctrl+Z, Ctrl+S writes `project.ron` and rewrites `crates/quillshade/Cargo.toml` / `src/lib.rs` (an unchecked domain loses its plugin line and `pub mod`, deletes `crates/quillshade/src/<domain>/`, disables its domain tab in the mainbar, and hides its content in the editor while keeping `quillshade/<domain>/`); an outside edit of `project.ron` reloads a clean tab and asks Keep mine / Reload for a dirty one, a broken edit keeps the old settings and the tab with a warning; Back / Forward reopen a closed Settings tab; the tab is not restored after a restart (`SHADER_EDITOR_DOMAIN=project [SHADER_EDITOR_DEMO=settings_dirty]`).
- [ ] Console filter (decision 0045): the console shows only the active domain's diagnostics and messages plus global and project lines; the header's "All domains" checkbox (click on its caption too) shows every domain's; the mainbar's error count is always the total; clicking another domain's diagnostic (with All domains on) opens its asset and switches the domain.
- [ ] View (decision 0035): the View menu lists "Zen mode `", a separator, "Back Ctrl+[" and "Forward Ctrl+]", a second separator, "Show project Ctrl+1", "Show console Ctrl+2", "Show properties Ctrl+3", each with its check mark; Ctrl+1 (also Super+1) hides / shows the left sidebar (the center takes its width), Ctrl+2 or the chevron in the console header hides the console down to its header bar ("Log - N errors, M warnings", Clear messages, the chevron flipped), Ctrl+3 the right sidebar (the editor content takes its width); `` ` `` turns Zen mode on: both sidebars and the whole console, header included, disappear — the mainbar, secondbar, editor topbar and editor statusbar stay; Ctrl+1/2/3 in Zen mode only move their check mark, and `` ` `` again shows exactly the checked panels; Ctrl+` does nothing; all four survive a restart (`config.ron` `show_left_sidebar` / `show_log` / `show_properties` / `zen_mode`; an old config opens with every panel shown and Zen off); `` ` ``, Ctrl+1/2/3 and Space do nothing while typing in a field, the palette, a dialog or an open menu; Ctrl+1 + LMB on the canvas drops no Constant; Tab toggles nothing (`SHADER_EDITOR_DEMO=menu:view`).
- [ ] Panes and layout (decision 0034): Project and Game Assets sit in Feathers panes with a header each, the right sidebar is one pane titled after the kind with subpanes (a material: Material, Preview, Hotkeys, Description — no Info; a function: Function, Hotkeys, Description; one node: Node, Parameters, Input defaults, Problems; a comment: Comment), console/logs a pane whose header holds the counts, Clear messages and the chevron; at the 800 px minimum width the center keeps about 400 px, the sidebars give way, editor topbar buttons wrap as whole items and no caption breaks inside its button; a labelled checkbox (Two sided, Tile 3x3) toggles on a click on its label; in the right sidebar and the texture form its box starts where the labels of the other rows do (no empty label column before it).
- [ ] Menus (decision 0034): main and RMB menus are Feathers menus — icons, right-aligned dim hotkeys, separators, a disabled item with its reason as tooltip; Up / Down / Home / End move, Enter or Space activate, Esc closes; a click outside only closes the menu (it neither selects a node nor opens another menu), a click on the open menu's name closes it; only one menu is open at a time; a menu near the window bottom opens above; a mainbar menu button looks active only while its menu is open — after an outside click, Esc, an item or another menu it is back to normal and the next click opens it again (design §1); after a pick the focus is back on the menu's button, so Space / Enter reopen it until a canvas click (Bevy's default) (`SHADER_EDITOR_DEMO=menu|tab_menu|game_file_menu[:2]`, `SHADER_EDITOR_INPUT=node_rmb|pin_rmb|menu_click|menu_close`).
- [ ] Back / Forward (decision 0041): View lists "Back Ctrl+[" and "Forward Ctrl+]" between Zen mode and the panel toggles, dimmed at the ends of the history (hover names why); switching tabs and then Ctrl+[ goes back to the previous tab, Ctrl+] forward again; a closed tab comes back (at the end of the secondbar); on a big graph a far pan or Fit then Back restores the camera, a small pan amends the current entry instead of adding one; the real mouse back / forward buttons navigate (X11 and Wayland); Ctrl+[ / ] on a Russian layout (the `х` / `ъ` keys); nothing happens while typing in a field, with the palette, a dialog or a menu open, or during a drag; navigating marks nothing unsaved and adds no undo step; Back past an asset that fails to load skips it with a console error and no dialog; Back / Forward at an end of the history logs nothing.
- [ ] Keyboard focus (decision 0035, Bevy's default): Tab / Shift+Tab walk every button, checkbox, select and field (mainbar with the domain tabs, secondbar, editor topbar, inline fields on nodes, editor statusbar, console header, right sidebar) with a focus ring, never into a hidden panel or the inactive editor kind's areas (`SHADER_EDITOR_INPUT=tab:30`); Enter / Space press the focused button once and open no palette; after a click on a toolbar button Space presses that button again, after a click on the canvas Space opens the palette; Tab stays inside an open dialog or the palette; Ctrl+Tab switches the tab and leaves no focus ring; hiding a panel (Ctrl+1/3, `` ` ``) that holds the focus drops it (Space then opens the palette); a click into a text or number field keeps the focus and typing goes there (`SHADER_EDITOR_INPUT=type_field` logs `ab`); Tab onto a number field dragged before selects its text: typing replaces the value and fires no hotkey (C, Delete); the first Tab after start logs one Bevy tab-group WARN.
- [ ] Right sidebar (decision 0031): its header follows the active tab's kind — Properties (graph), Generated File, Curve, Constants, Image, Texture, Gradients, Environment, Project Settings — and with no tab open reads Properties / "Nothing open."; a generated-file tab shows only path, language, source and line count there (Copy / Source / Open externally are in the editor topbar); switching tabs back and forth shows the current content of each kind (select a node, switch to a curve tab and back: the node's properties).
- [~] Browser (the **Project** panel header): double click opens an asset (a single click does not); only the active tab's asset is highlighted, folders never; unsaved assets show an orange dot; RMB on a folder or the empty space below the tree → New Pbr/Unlit/2D/Fn/Curve/Folder in that folder; RMB → Rename / Move / Delete (with confirmation, autogen is deleted); dragging an asset onto a folder moves it; "Show generated WESL/Rust" opens a read-only tab (code icon, `wesl`/`rust` watermark, highlighted, line numbers; wheel / Shift+wheel scroll; Ctrl+C and the Copy button copy the file; "Open in the default application" works; the tab refreshes after Ctrl+S of its asset; switching back to the graph tab keeps its camera).
- [ ] Game Assets panel (design §4.2): below Project, with Material active lists only `.png` / `.ktx2` files under the game's `assets/` (any case) and the folders holding them, never `assets/quillshade/`; image icon; folders collapse independently of the Project tree; no create / rename / move / delete, dragging a row onto a folder does nothing (dragging an image onto a graph drops it, see below); a file added / deleted in `assets/` appears / disappears without a restart while Assets → Generate causes no refresh loop; RMB on an image → "Create Texture Asset" creates `quillshade/material/textures/…/<name>.texture.ron` (shown in Project); on a file that already has one the item is dimmed, does nothing and its tooltip names the asset (`SHADER_EDITOR_DEMO=game_file_menu`).
- [ ] Drag and drop onto a graph (design §4.3): dragging a Game Assets image onto empty canvas adds a `TextureSample` at the drop point referencing its Texture asset (selected, Properties show it); an image without one creates `quillshade/material/textures/…/<name>.texture.ron` (`rock_albedo.png` → `textures/rock_albedo_2`, a log line, shown in Project), one with one reuses it; dropping onto a texture node (`albedo` in rock_wet) sets its texture (thumbnail changes) and adds no node, onto any other node adds a new node there; Ctrl+Z removes the node / restores the old texture in one step while the created asset stays; a Texture asset or `Internal` → `default` dragged from Project works the same; dropping a material, folder or a non-image does nothing (`SHADER_EDITOR_INPUT=drop_game_file SHADER_EDITOR_INPUT_FILE=textures/rock_normal.png [SHADER_EDITOR_INPUT_NODE=n02]`, on a copy of the sample).
- [ ] Drag and drop of Project assets (design §4.11): a Function dragged onto a graph adds its call node at the drop point (selected; onto any node too); dragged onto its own graph it adds nothing and logs "Function `…` cannot call itself (recursion)"; a Curve onto empty canvas or a node without a curve param adds a `Sample Curve` reading it, onto a `Sample Curve` (`n08` in curve_bands) sets its curve and adds no node; Ctrl+Z undoes each drop in one step (`SHADER_EDITOR_INPUT=drop_game_file SHADER_EDITOR_INPUT_FILE=quillshade/material/common/steps.curve.ron [SHADER_EDITOR_INPUT_NODE=n08]`, on a copy of the sample).
- [ ] Image tab (design §4.4): double-clicking a game image (not a single click) opens a read-only tab (image icon, `image` watermark, title `assets/<path>`); the image is fitted to the view keeping its aspect (resize the window), transparent parts show a checkerboard, the editor topbar shows `WxH | format | mips`, R | G | B | All, Tile 3x3 (repeats the image) and the zoom; the wheel zooms around the pointer (`SHADER_EDITOR_INPUT=texture_zoom` with `SHADER_EDITOR_OPEN=@game/textures/sprite.png`), a drag pans, a double click fits, and switching to another image tab and back keeps each tab's zoom; both a `.png` and a `.ktx2` (`textures/rock_albedo.ktx2`) show; a corrupt file shows the decode error as text and `n/a`; opening it again activates the same tab; overwriting the file on disk updates the shown image; the right sidebar (titled Image) offers "Create Texture Asset" or names the Texture asset pointing at the file; the tab is restored on the next launch (`SHADER_EDITOR_OPEN=@game/textures/rock_albedo.ktx2`).
- [ ] Texture tab (design §4.4): double-clicking a Texture asset opens it (Texture icon, see Icons; `texture` watermark); the form lists Path, sRGB, Expand grayscale (each with the "rebuild needed" hint), Sampler "Default" and, once it is off, address U/V/W, mag/min/mipmap filter, LOD min/max clamp, anisotropy; every change shows in the preview right away (unsaved, the tab gets the orange dot), Ctrl+Z / Ctrl+Y step back and forth (a dragged number field is one step), Ctrl+S saves and regenerates; the wheel zooms around the pointer (`SHADER_EDITOR_INPUT=texture_zoom`, `textures/atlas` shows hard Nearest pixels, `textures/water_normal` a smooth Linear blend), a drag pans, a double click fits, "Tile 3x3" shows Repeat / Clamp to edge around the image; typing the path of another Texture asset's file + Enter shows an error dialog and the field returns to the old path, an invalid path (`../x.png`, `x.jpg`) likewise, a free file is taken (a missing one gives W109 in the log); anisotropy 8 with a Nearest filter (or LOD min above max) shows the E013 error text instead of the image and E013 in the right sidebar / the log, switching all filters to Linear brings the image back; with the path of a file an unsaved Texture tab moved away from, another asset's path edit and Game Assets "Create Texture Asset" are refused until that tab is saved; the tab is restored on the next launch (`SHADER_EDITOR_OPEN=textures/water_normal.texture.ron`).
- [ ] Texture node thumbnails (design §4.5): `TextureSample` / `TextureObject` / texture parameter nodes show a 128×128 thumbnail left of the output pins, inputs below (rock_wet: rock albedo and normal; water: the water normal also on both TextureSample nodes wired to it; an empty Texture property shows the default checker); an image that is not square is letterboxed; edit the path or sRGB / sampler of that Texture asset in its open tab and switch back — the thumbnail shows the unsaved change (Ctrl+Z there and back again: the old image); a missing file or unknown Texture asset shows "n/a" (`SHADER_EDITOR_OPEN=env/rock_wet.material.ron`).
- [ ] Texture tab Easy / Advanced (decision 0028): one editor topbar row — Easy | Advanced, in Easy "Use for" Default | Pixel art | UI | 3D | Normal map | Ground (exactly one highlighted, read back from the file: `atlas` Pixel art, `water_normal` Normal map, `sprite` Default — no sampler key; `rock_normal` — linear, no sampler — opens in Advanced; hover tells what each sets; a sampler customised in Advanced to match no preset disables Easy, its tooltip says why), R | G | B | All, Tile 3x3, the zoom; Easy hides the form, a preset is one Ctrl+Z step and sets sRGB (off only for Normal map, decision 0042); Advanced shows the form — turning "Default" off shows Linear filters and Clamp to edge (Bevy's `ImagePlugin::default()`), so the tiled preview looks the same; the right sidebar (titled Texture) shows the image path and `WxH | format | mips`; R / G / B show that channel in grey, All the image, only one at a time (preview only: no unsaved dot, thumbnails unchanged) (`SHADER_EDITOR_DEMO=texture_channel:1`).
